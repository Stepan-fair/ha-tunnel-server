## Python TemporaryDirectory

[PSF-2026-42](https://github.com/psf/advisory-database/blob/main/advisories/python/PSF-2026-42.json) / CVE-2026-12345 требует конкурентной записи атакующего в удаляемое дерево. Проверенный CPython3.13.16 содержит старую обработку PermissionError с reset permissions в tempfile._rmtree; оснований считать проблему исправленной по номеру версии нет. Metadata содержит несколько fix-коммитов и revert, а fd-safe rmtree не устраняет все варианты изменения flags.

В Server единственный runtime TemporaryDirectory — backup.restore_state: stage под `/data`, приватный parent0700, владелец UID10001 после drop privileges, сам stage0700 и файлы0600. Содержимое проходит AES-GCM, ограничения размера и фиксированный allowlist; SQL восстанавливается из проверенных строк, произвольные пути/symlinks/сырая SQLite не извлекаются. Восстановление сериализовано и предназначено только для пустого назначения. Remote Client не может писать туда во время cleanup. Client не использует TemporaryDirectory в runtime. В инструментах stage содержит доверенные исходники либо строго ограниченные regular файлы OCI; ни один инструмент не принимает архив для extractall.

Это отсутствие необходимого удалённого writer в текущей модели, а не исправление stdlib. Компрометация того же UID/доверенного Supervisor снимает эту предпосылку. Нужен повторный анализ при появлении общего writable volume, внешних subprocess writers или нового extract API; совместимый upstream fix следует включить при доступности. Переход на Python prerelease ради scanner metadata не выполняется.

Повторное чтение именно этих двух OCI проверило SHA архива, manifest и каждого layer descriptor. В обеих ролях фактический `tempfile.py` — 32643 bytes, SHA256 `7350d7f75ca8d6e4752c377777a315dc26eb4ecd3b6c9c0951bffddc576f030f`; `shutil.py` — 57130 bytes, SHA256 `11c32fd568588e38463fdf281caa7ef0edbf3d64daf7961f0e7e68d779528731`. Вывод выше основан на этих байтах, а не на более раннем диагностическом образе.
