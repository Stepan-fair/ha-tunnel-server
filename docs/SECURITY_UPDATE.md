# Обновление безопасности HA Tunnel 0.3.2

Обычное обновление Server/Client сохраняет адреса, ключи и действующие подключения. Capabilities клиента больше не блокируют серверные запреты. Проверка настоящей административной роли HA выполняется на каждом обращении к панели; если HA API недоступен, панель закрывается, туннель продолжает работать согласно сохранённой политике.

MQTT используется только для показаний. Старые кнопки «Пуск» и «Пауза» удаляются из discovery; автоматизации, вызывающие эти кнопки, нужно заменить административными действиями в панели Server. Существующие 17 показаний на объект сохраняют unique_id. Публикация старых или новых command сообщений не меняет доступ.

Восстановление переносимой .hatb копии сохраняет адреса, историю и статистику, но отзывает старые ключи и коды всех восстановленных подключений. В разделе «Отозванные» выдайте каждому клиенту новый код. Это предотвращает возврат ключа из копии, созданной до отзыва. Обычное обновление не выполняет эту процедуру.

Полное восстановление диска или HA backup способно откатить само приложение вместе с базой. Без внешнего актуального журнала отзывов приложение не может обнаружить произвольный откат всей машины. После такого восстановления восстановите актуальную версию, отзовите прежние подключения и выдайте свежие коды; при утрате контроля над сервером замените и CA, и ключи. Не используйте старые копии состояния как автоматический способ вернуть доступ.

Сервер работает с UID/GID 10001 после ограниченной миграции своего /data, без возможности повышения привилегий. FRP и Nginx не получают Supervisor token в окружении. Client сохраняет права HA API и доступа к конфигурации, необходимые для подготовки HTTP; читать .storage/auth для проверки пользователя больше не требуется.

API ограничивает запросы по адресам и клиентам, не вытесняет активные бюджеты и ограничивает параллельные обработчики. Relay ограничивает соединения до 256 суммарно и 32 на клиент. Большие распределённые атаки требуют внешней защиты proxy/сети. HSTS max-age=31536000 включён для доверенного HTTPS API и шлюза, без includeSubDomains/preload.

TLS защищает браузер–NPM и Server–Client. Server/NPM являются доверенными узлами и видят HTTP запросы. Эта версия не скрывает пароли и данные от владельца или компрометированного сервера; для этого нужна другая сквозная архитектура.

Сборки проходят Linux проверки настоящих FRP/Nginx/Mosquitto без пропусков до публикации. Базовый образ и колёса зависимостей закреплены хешами; формируются SBOM и provenance. Проверка подписи образа Supervisor не обеспечивается этим изменением: установка по тегам сохраняет доверие к владельцу GitHub/GHCR. Защитите учётные записи MFA и ограничьте право публикации.
