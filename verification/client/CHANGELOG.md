## 0.3.3

- Исправлено управление доступом в локальном HTTP интерфейсе HA: идентификаторы команд создаются через browser CSPRNG без требования randomUUID. Все исправления безопасности 0.3.2 сохранены.

# 0.3.2 — защита панели и служебных ключей

- Актуальная проверка административной роли через HA API, без чтения .storage/auth.
- FRP больше не наследует Supervisor token или другие служебные credentials.
- Обновлённая базовая система, установка зависимостей по хешам, Linux CI перед выпуском.
- Действующие подключения и TLS проверки сохраняются.

# 0.3.1 — проверка связи при IPv6 и IPv4

- Проверка TLS автоматически выбирает рабочий адрес, если первый IPv6 недоступен. Проверка сертификата и имени сервера сохраняется.

# 0.3.0 — восстановление и компактная панель

После отзыва новый код того же подключения вводится без переустановки и подготовки HA. Отдельная подтверждаемая замена привязки; ошибки сохраняют прежние данные. Компактная статистика с русскими подписями и десятичными единицами, инструкция в панели. Отдельный репозиторий Client и сохранение MQTT Discovery между перезапусками. Выпуск amd64; приёмка новой версии отражается в ACCEPTANCE.

# 0.2.0 — статус доступа и сущности HA

Статус сервера доступен при паузе/истечении/отзыве. Снятие паузы автоматически возвращает FRP без подготовки HTTP и перезапуска Core. MQTT Discovery:17сущностей подключения, RTT, скорость и трафик. Повторный код того же клиента применяется без изменения адреса и настроек HA. Сохранена совместимость со старым Server. Предварительный выпуск; оставшиеся проверки перечислены в ACCEPTANCE.

# 0.1.3 — восстановление панели

После успешного подключения убирается временное сообщение о потере связи при обновлении Client или перезапуске HA.

# 0.1.2 — состояние реального туннеля

Индикатор использует локальное имя прокси из API frpc 0.71.0. Исправлено ложное ожидание при работающем соединении.

# 0.1.1 — совместимость с HTTP API HA 2026.8+

Настройка через штатный API, сохранение существующих прокси и параметров. После перезапуска требуется штатное подтверждение HA; до него туннель не публикуется. YAML используется только на старом HA. Добавлено разрешение Core API через Supervisor, пользовательский токен не нужен.

# 0.1.0 — предварительная версия

Привязка одним кодом, безопасная подготовка HTTP-настроек HA, закреплённая CA и состояние туннеля. Сквозная приёмка на HA OS ещё не выполнена.
