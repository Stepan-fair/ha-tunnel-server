# Установка HA Tunnel Client с нуля

Версия инструкции: 0.3.1 · 4 октября 2026. Инструкция обновляется вместе с изменениями мастера и подключения.

Client устанавливается на Home Assistant OS в подключаемом доме. Публичный IPv4, проброс входящих портов и собственный домен здесь не нужны. Нужен исходящий доступ к HTTPS и TCP7000 сервера, а также код от его администратора.

1. Откройте [добавление репозитория Client](https://my.home-assistant.io/redirect/supervisor_addon_repository/?repository_url=https%3A%2F%2Fgithub.com%2FStepan-fair%2Fha-tunnel-client). Если ссылка не открылась: «Настройки → Приложения → Магазин → ⋮ → Репозитории», добавьте `https://github.com/Stepan-fair/ha-tunnel-client`.
2. Установите **HA Tunnel Client**, включите запуск при загрузке и автоматическое обновление. Панель доступна активным администраторам этого HA; список определяется автоматически, вручную вводить ID не нужно.
3. Запустите Client, откройте его веб-интерфейс и вставьте код. При новой установке мастер предложит подготовить HTTP для туннеля. Он сохраняет прежние доверенные прокси и добавляет только loopback. Если нужен перезапуск HA, следуйте подсказкам; подготовка относится только к этому HA.
4. На актуальном HA пробная настройка HTTP требует подтверждения в течение пяти минут. Проверьте, что HA открывается, и подтвердите результат. Без подтверждения HA возвращает прежние настройки. Во время подготовки не меняйте HTTP в другом окне. Старые версии без штатного HTTP API используют проверенный YAML-путь; неоднозначную конфигурацию мастер попросит уточнить.
5. Получите состояние «Home Assistant доступен», затем проверьте свой адрес с телефона через мобильный Интернет и настройте Companion. Приём и передача показываются со стороны Client; счётчики относятся к трафику туннеля.

После паузы или истечения срока Client сам ожидает разрешения Server. Дополнительная подготовка HA не нужна. После отзыва введите новый код **того же подключения** в форме восстановления. Ошибка сети или неверный код сохраняют прежние данные. Для перехода на другой сервер или объект используйте отдельное подтверждаемое действие «Другое подключение».

Обновления Server и Client независимы: каждый HA подписан только на свой репозиторий. Обычное обновление или перезапуск Client сохраняют привязку и не требуют перезапуска Core. При переносе сохраняйте приватное состояние Client; повторная установка в другой репозиторий имеет отдельное хранилище. Существующий альтернативный доступ можно оставить до проверки нового.


## Как получить обновление

В карточке приложения HA включите «Автообновление». Новые версии приходят из репозитория соответствующего приложения; Server и Client обновляются независимо. HA проверяет их по расписанию, поэтому публикация на GitHub не означает немедленную установку. Если нужно обновить сейчас, откройте магазин приложений, проверьте обновления, затем в карточке нажмите «Обновить». После завершения проверьте номер версии и состояние подключения.
