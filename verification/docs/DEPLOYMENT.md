# Развёртывание HA Tunnel

Для новой установки используйте пошаговые инструкции [Server](SERVER_INSTALL.md) и [Client](CLIENT_INSTALL.md). Они соответствуют мастеру версии0.3 и двум раздельным репозиториям. Ниже сохранены подробности сетевой схемы и восстановления.

Предварительная версия: сначала выполните [приёмку](ACCEPTANCE.md) в тестовой среде. Инфраструктурные адреса, учётные записи и ключи конкретного владельца в этот документ не входят.

## Требования

Server: HA OS с белым адресом, возможность пробросить TCP 7000, Nginx Proxy Manager и управляемый DNS-домен. Client: HA OS в любой сети с исходящим доступом к HTTPS API и TCP 7000 сервера. Локальный Core клиента должен использовать HTTP на 8123.

Проверьте свободное место, сохраните небольшие копии изменяемых DNS/NPM/NAT-настроек. Для этих изменений полная копия HA не требуется. До публичной установки выполните Linux FRP-тесты, контейнерные сборки и проверку манифестов Supervisor.

## Однократная подготовка Server

1. Установите Server из подготовленного репозитория приложений. Настройте `base_domain`, HTTPS `server_url`, внутреннее имя NPM, разрешённые ID администраторов и уже занятые `reserved_names`. Пример домена далее — `example.org`.
2. Создайте wildcard A `*.example.org` на белый адрес сервера. Сохраните существующие точные записи: они имеют приоритет. Не занимайте имена действующих сервисов.
3. В NPM получите сертификат `*.example.org` через DNS-01. Используйте поддерживаемого DNS-провайдера и минимальные необходимые права. Проверьте автоматическое продление; наличие сертификата само по себе этого не доказывает. Для REG.RU сначала проверьте доступность и совместимость DNS-плагина в установленной версии NPM.
4. Создайте wildcard Proxy Host `*.example.org` на внутреннее DNS-имя Server, HTTP порт 8080. Включите WebSockets, Force SSL и wildcard-сертификат.
5. Создайте точный Proxy Host для `server_url`, например `tunnel.example.org`, на тот же Server, HTTP порт 19001. Включите HTTPS. Этот host обслуживает только API.
6. Проверьте, что NPM принудительно задаёт `X-Real-IP $remote_addr` и `X-Forwarded-Proto $scheme`. Не принимайте их от внешнего клиента и не создавайте дублирующие `proxy_set_header`. Gateway нормализует заголовки перед FRP. Фактическую цепочку нужно проверить на тестовом HA.
7. После проверки конфликтов портов и firewall создайте одно правило WAN TCP 7000 на LAN-адрес HA Server, TCP 7000. Административные и внутренние порты не публикуйте. Существующие маршруты оставьте без изменений.

Server запоминает IP NPM при запуске. Если адрес контейнера NPM изменился, перезапустите Server. Имя службы регистрации резервируется автоматически; остальные действующие поддомены внесите в `reserved_names`.

## Подключение Client

Добавьте реальный Git URL репозитория с упакованными приложениями в магазине HA OS. В Server создайте клиента и скопируйте одноразовый код. Установите Client на удалённом HA, откройте его панель и вставьте код.

В HA 2026.8+ мастер использует штатную настройку HTTP: сохраняет существующие trusted_proxies, добавляет только доверие `127.0.0.1/32` и ожидает подтверждение администратора в течение пяти минут после пробного перезапуска Core. Без подтверждения HA автоматически возвращает прежние параметры. YAML при этом не изменяется. Во время подготовки не редактируйте HTTP в других окнах.

Только на старом HA без штатного HTTP API мастер проверяет YAML, добавляет доверие loopback, проверяет конфигурацию и запрашивает перезапуск Core. Неоднозначные include/secret/якоря HTTP требуют ручной настройки; подробность появится в панели.

Если запрос перезапуска не удался, нажмите «Повторить подготовку»: состояние ожидания сохраняется. Публикация начинается только после принятия Core запроса с forwarded-заголовками. Обычный перезапуск Client сам YAML не меняет и Core не перезапускает.

Поддомены следующих клиентов создаются без отдельных DNS/NPM-правил. Проверьте работу из внешней сети, Companion, отзыв активного WebSocket и доступ к локальному HA при выключенном туннеле.

## Откат

Остановите Client/Server; отключите только добавленное правило TCP 7000 и новые Proxy Hosts/DNS-записи. Для клиента точечно уберите добавленное доверие loopback либо восстановите `.ha-tunnel.bak` после проверки последующих правок. Перед удалением Server сохраните зашифрованный экспорт его состояния.
