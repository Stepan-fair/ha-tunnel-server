# Установка HA Tunnel Server с нуля

Версия инструкции: 0.3.1 · 4 октября 2026. При изменении мастера, портов или порядка установки эта инструкция обновляется вместе с приложением.

Server устанавливается на Home Assistant OS в доме, через который другие дома получают удалённый доступ. Для него нужны собственный домен, публичный постоянный IPv4, доступ к настройкам DNS и роутера, а также Nginx Proxy Manager (NPM). Client устанавливается отдельно в каждом подключаемом доме.

## 1. Подготовьте Интернет и домен

Уточните у провайдера: «Мне нужен публичный постоянный IPv4 с разрешёнными входящими TCP-подключениями». Затем в настройках роутера откройте раздел «Интернет» или «WAN» и найдите IPv4. Это адрес внешнего подключения, а не локальный адрес HA вроде `192.168.…`.

Адреса `10.…`, `192.168.…`, `172.16.…`–`172.31.…` и `100.64.…`–`100.127.…` не подходят как непосредственный публичный WAN. Если перед вашим роутером стоит ещё один ваш роутер, настройка возможна через оба; иначе уточните условия у провайдера. Сервис «мой IP» показывает выходной адрес сети, но не доказывает доступность входящих портов или постоянство IP.

Используйте свой домен. Далее `example.org` — только пример; при установке поля пустые. У DNS-провайдера создайте wildcard-запись `*.example.org` типа A на публичный IPv4. Существующие точные записи не удаляйте. Имя `tunnel.example.org` будет адресом регистрации клиентов.

## 2. Установите только Server

Откройте [добавление репозитория Server в Home Assistant](https://my.home-assistant.io/redirect/supervisor_addon_repository/?repository_url=https%3A%2F%2Fgithub.com%2FStepan-fair%2Fha-tunnel-server). Выберите свой HA, подтвердите добавление, затем установите **HA Tunnel Server** в магазине приложений. Если ссылка не открылась: «Настройки → Приложения → Магазин → ⋮ → Репозитории», вставьте `https://github.com/Stepan-fair/ha-tunnel-server`.

Включите «Запуск при загрузке» и «Автоматическое обновление», нажмите «Запустить», затем «Открыть веб-интерфейс». Пока настройка не закончена, работает только защищённый мастер: подключения клиентов ещё не принимаются. Первый запуск доступен администратору HA. Если права не подтвердились, проверьте вход под администратором и журнал приложения; пустой список пользователей не открывает доступ всем.

## 3. Установите Nginx Proxy Manager и пройдите мастер

До заполнения мастера установите **Nginx Proxy Manager** из магазина приложений HA и запустите его. Если его нет в магазине, добавьте [репозиторий Community Apps](https://my.home-assistant.io/redirect/supervisor_addon_repository/?repository_url=https%3A%2F%2Fgithub.com%2Fhassio-addons%2Frepository). Затем перезапустите только HA Tunnel Server и откройте его веб-интерфейс: мастер заново обнаружит внутреннее имя NPM. Если обнаружение недоступно, найдите «Имя хоста» на странице информации установленного приложения NPM и вставьте его в поле Nginx Proxy Manager. Не указывайте публичный адрес панели или порт 81.

Введите основной домен и адрес регистрации `https://tunnel.ВАШ-ДОМЕН`. Если NPM уже установлен, мастер предложит его внутреннее имя. Подтвердите доступ текущего администратора. В дополнительные занятые имена внесите используемые поддомены, чтобы они не выдавались клиентам. Сохраните настройки; перезапустится только HA Tunnel Server.

Часовой пояс берётся из HA, если штатный API доступен. NPM и архитектура определяются тем же способом. Автоматическое обнаружение может быть недоступно; тогда мастер объясняет, какое значение указать вручную. Настройки хранятся в штатных опциях приложения. Если они изменились в другом окне, обновите страницу и повторите сохранение.

## 4. Настройте сертификат и NPM

Откройте панель уже установленного Nginx Proxy Manager. В **SSL Certificates → Add SSL Certificate → Let's Encrypt** укажите `*.ВАШ-ДОМЕН` и при необходимости сам основной домен. Выберите **Use a DNS Challenge**, своего DNS-провайдера и предоставьте только необходимые ему права. DNS-01 нужен для wildcard-сертификата. Сохраните данные в NPM; не передавайте ключ DNS в коде подключения или в чате. Если вашего DNS-провайдера нет в списке, сначала выберите поддерживаемый способ DNS-01. Сертификат без работающего продления не обеспечивает длительную доступность.

В разделе **Proxy Hosts** создайте два правила. Точное внутреннее имя установленного Server показано в его настройке; после установки из другого репозитория оно меняется.

| Поле NPM | Сайты клиентов | Регистрация |
| --- | --- | --- |
| Domain Names | `*.ВАШ-ДОМЕН` | `tunnel.ВАШ-ДОМЕН` |
| Scheme | `http` | `http` |
| Forward Hostname / IP | внутреннее имя HA Tunnel Server | то же имя |
| Forward Port | `8080` | `19001` |
| Websockets Support | включить | можно включить |
| SSL Certificate | wildcard-сертификат | тот же сертификат |
| Force SSL | включить | включить |

Стандартная конфигурация NPM должна выставлять `X-Real-IP` из реального адреса посетителя и `X-Forwarded-Proto` из схемы запроса. Не добавляйте повторные заголовки поверх стандартных и не принимайте эти значения от посетителя. Не создавайте публичный Proxy Host на Ingress или служебные порты.

## 5. Настройте роутер и проверьте

Закрепите локальный адрес HA Server в DHCP роутера. Для HTTPS нужен входящий TCP **443** на HA/NPM; если правило уже есть, используйте его. Создайте TCP **7000 → локальный адрес HA Server:7000**. Для HTTP-01 может понадобиться TCP80, но описанный wildcard DNS-01 сам по себе не требует этого порта. Порты 8099, 19000, 19001 и остальные внутренние порты отдельно в Интернет не публикуйте.

В мастере можно проверить DNS, HTTPS и внешний IPv4. Запрос внешнего IP идёт на [ipify](https://www.ipify.org/); сервис видит внешний адрес, но приложение не отправляет ему конфигурацию HA или ключи. Проверку можно пропустить. WAN берётся из введённого вами адреса роутера. Отметку о постоянном IP ставьте после подтверждения провайдером. «Не удалось проверить» означает неизвестный результат, а не доказанный серый IP. До запуска публичного API или без NAT loopback локальная проверка HTTPS может не пройти.

Отключите Wi-Fi на телефоне и откройте адрес регистрации с мобильного Интернета: `/health` должен вернуть `status: ok`. Затем подключите Client и проверьте его сайт, вход в HA и Companion из внешней сети. Эта проверка нужна даже при зелёных локальных показаниях. В дальнейшем проверяйте продление сертификата и наличие свежего ответа HA.

## Управление и восстановление

Создайте код в разделе «Подключения» и передайте его владельцу Client. Код действует 15 минут. Для действующего неиспользованного кода есть «Показать код»; для нового — «Выдать новый код». Настройте бессрочный доступ или удобный смешанный срок. Пауза временно прерывает доступ, пуск возобновляет его. После истечения пуск повторяет ранее заданный срок.

Отозванное подключение исчезает из основного списка и остаётся в «Отозванных». Выдача нового кода восстанавливает тот же адрес, сущности и статистику; срок отсчитывается с использования кода. «Удалить окончательно» освобождает домен для нового объекта; старые ключи не подходят. История действий остаётся в журнале после перезапуска и удаления объекта.

MQTT предоставляет только показания; пуск, пауза и сроки изменяются в административной панели Server. Прежние MQTT кнопки в версии 0.3.2 отключены для защиты от неадминистративных команд.

Перед переносом сохраните защищённый экспорт состояния. Экспорт включает ключи и историю; храните его приватно вместе с паролем отдельно от файла. Восстановление .hatb сохраняет историю и адреса, но отзывает все старые ключи и коды: выдайте новые коды в «Отозванных». Обычное обновление действующие ключи сохраняет. После полного отката диска/HA backup также отзовите старые подключения и выполните перепривязку. Если история превысила предел экспорта, сохраните CSV и используйте согласованную копию всего состояния с этой мерой защиты. Подробности — [обновление безопасности](https://github.com/Stepan-fair/ha-tunnel-server/blob/main/docs/SECURITY_UPDATE.md) и [проверка установки](https://github.com/Stepan-fair/ha-tunnel-server/blob/main/docs/ACCEPTANCE.md).


## Как получить обновление

В карточке приложения HA включите «Автообновление». Новые версии приходят из репозитория соответствующего приложения; Server и Client обновляются независимо. HA проверяет их по расписанию, поэтому публикация на GitHub не означает немедленную установку. Если нужно обновить сейчас, откройте магазин приложений, проверьте обновления, затем в карточке нажмите «Обновить». После завершения проверьте номер версии и состояние подключения.
